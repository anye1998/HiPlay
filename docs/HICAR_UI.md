# 接收端界面：三个页面、显示模式与自适应

这个 APK 只有一个 Activity（`HiCarHostActivity`），它画三个页面。不再有 CarPlay 首页、
设置 Activity、集群/HUD 页面。

## 一、三个页面

| 页面 | 什么时候出现 | 有什么 |
| --- | --- | --- |
| 连接页 | 空闲、准备热点、广播中、等待手机、失败、有线等待认证 | 6 位连接码、开始/停止无线、首次配对说明、最近 12 行日志、右上角「设置」入口 |
| 会话页 | 手机认证通过之后（`Authenticated` / `ControlChannelReady` / `Streaming`） | 手机画面（等比缩放）、状态、设置、停止、返回/主页、麦克风、日志开关 |
| 设置页 | 任意时刻点「设置」 | 显示、声音、连接、诊断、关于 |

设置页是**叠在**当前页面之上的一层，不是另一个 Activity。原因很实际：`TextureView` 的
`SurfaceTexture` 属于窗口，窗口一旦被另一个 Activity 覆盖并暂停，镜像画面就会黑掉；在同一个
Activity 里叠一层，解码器和会话都不受影响，改完设置直接看到新效果。

### 权限没给时的样子

连接页「开始」下面会写**还差哪些权限**（按系统给的名字，Android 12L 及以下是 `ACCESS_FINE_LOCATION`，
13 起是 `NEARBY_WIFI_DEVICES`），旁边一个「打开应用权限」直达本应用的系统权限页。

这不是提示语而已：`startReceiver()` 自己有一道闸门，任何路径（按钮、插数据线唤醒、恢复的界面）
在权限不齐时都只发起申请、不打开任何无线电。以前「开始无线」这条路径绕过了检查，结果是手机把
HiChain 走完、车机却开不出热点，界面上只留一句「失败：hotspot」——看起来像认证出了问题。

### 连接页那个按钮只管无线

按钮有三态：没运行时是「开始」；运行时无线开着是「停止无线」；无线关着是「开始无线」。

有线连接由数据线自己驱动，不受这个按钮控制——插着线时按「停止无线」只关热点和广播，画面照旧
走线。会话页右上角的「停止」仍然是全部停止（两者语义不同，是因为一个在连接页、一个在正看着的
画面上）。完整规则见 `docs/HICAR_WIRED.md` 第五节。

## 二、显示模式

`HiCarWindowMode`（`shared/.../hicar/HiCarDisplaySettings.kt`）三选一，存在
`hicar-display` 偏好里，启动时读取，设置页改动后立即应用：

| 值 | 状态栏 | 底部导航栏 |
| --- | --- | --- |
| `FULLSCREEN`（默认） | 隐藏 | 隐藏 |
| `STATUS_BAR` | 显示 | 隐藏 |
| `STATUS_BAR_AND_NAVIGATION` | 显示 | 显示 |

实现要点：

- 三种模式都执行 `WindowCompat.setDecorFitsSystemWindows(window, false)`，系统栏不会背着我们
  改变内容区域大小；内容自己的内边距（`Content()` 里的 `windowInsetsPadding`）决定可见系统栏
  占多少位置。
- 全屏模式保留 `BEHAVIOR_SHOW_TRANSIENT_BARS_BY_SWIPE`：车机没有 Home 键时，划一下还能唤出
  系统栏，不会被锁在应用里。
- 切换模式不需要断开连接，也不需要重建 Activity。

### 画面比例为什么不能跟着系统栏立刻变

`his_video_formats`（含 `scr-w`/`scr-h`/`width`/`height`/`dpi`）只在 RTSP 握手的
`GET_PARAMETER` 里回答一次，视频端口本身也是每次 DMSDP 协商重新分配的；这套协议里没有「现在换一个
尺寸重新编码」的消息。所以切换显示模式后：

- **当前会话**：窗口按新的可用区域重新排布，画面按自己的比例等比缩放，多出来的地方留黑边；
  手机仍按旧尺寸编码，不会因为窗口变矮而重新编码。
- **下次连接**：`startReceiver()` 用 `contentPixels()` 量出「面板 − 当前显示模式下可见的系统栏」，
  直接把这个区域作为 offer（例如 1920×1032，而不是 16:9 的 1920×1080）。手机接受时，窗口与画面
  同比例，没有黑边；手机坚持自己的比例时仍然会留一点。
- **想立刻应用**：设置页「显示」节里有一个「按当前区域重新取画面（会重连）」按钮，它执行
  Stop → 1.2 s → Start，让手机重新编码。会中断声音/通话，所以不做成切换显示方式时的自动行为。

`HiCarDisplaySize.fitTo()` 负责把区域按质量上限等比缩小并取偶数（H.264 不接受奇数宽高），
`HiCarVideoSettings.offerSize()` 调用它；`best()` 的 16:9 档位仍保留给「拿不到窗口 insets」的
退化情况。

## 三、画面为什么不会畸形

`HiCarVideoFit.fit(videoAspect, 容器宽, 容器高)` 返回**保持视频宽高比**的最大矩形，多出来的
地方留黑边（letterbox）。`TextureView` 的尺寸就是这个矩形，所以：

- 画面永不被拉伸：宽容器按高度贴合，高容器按宽度贴合；
- 触控坐标正确：`sendTouchAt` 用的是这个视图自己的宽高，视图等于画面，映射才对得上；
- 视频比例来自解码器的真实输出（`HiCarController.onPictureSize`），不是我们请求的分辨率；
  手机给 4:3 就按 4:3 显示。

纯算术放在 `HiCarVideoFit` 里，由 `HiCarVideoFitTest` 覆盖（宽容器、高容器、正好、退化尺寸、
异常比例）。

## 四、连接中改设置

- **显示**：`selectWindowMode()` 立刻 `applyWindowMode()`，画面重新按新区域等比缩放。
- **声音（车速增益）**：参数存 `hicar-speed-volume`，同时调用
  `HiCarController.refreshSpeedVolume()`，把运行中的音频通路换成新的曲线；不需要重连。
  音乐始终跟随曲线，导航与通话各有一个开关（默认都跟随），关掉的那条通道增益置 0，
  下一次写入 PCM 时生效。设置页还会显示**当前真正在用的来源**（车辆总线 / 定位 / 保持 / 无），
  由 `HiCarSpeedMonitor` 每秒通过 `HiCarSpeedStatus` 推送，不是只显示偏好里选的那一项。
- **连接**：机型码、蓝牙地址（可从系统读取）、连接码、重置配对。改动在下一轮连接生效（这些值在
  会话开始时已经发给手机）。

  「从系统读取本机蓝牙地址」用本应用自己的 adb 通道（`HiCarBluetoothAddress`）：先
  `settings get secure bluetooth_address`，为空或是 `02:00:00:00:00:00` 这样的占位值再读
  `dumpsys bluetooth_manager` 里蓝牙服务自己的 `address:` 行。两条都不需要 root，但要 adbd
  已经信任本应用（上面的「获取 ADB 授权」）。读到就填进输入框，**不自动派生标识**——改标识等于
  让手机当一台新车重新配对，所以那一步留给下面的「按蓝牙地址派生本机标识」。三句提示分别对应
  三种状态：都没有可用地址、地址对但标识没按它派生、两者都已经一致。

## 五、验证情况（2026-11-22，MuMu 模拟器，无实车）

- 连接页、设置页、显示模式切换（全屏 → 状态栏 → 状态栏+导航栏）在模拟器上确认：状态栏出现
  且内容下移、没有遮挡；模式重启后保持。
- 界面整体改为深色（`darkColorScheme()`）：夜间的车机与全屏画面一致，连接页/设置页不再是一块白。
- CarPlay 时期的布局、图标、多语言字符串已删除，图标换成矢量 `ic_hicar`，应用名 `HiCar`。
- 模拟器镜像没有蓝牙，接收端停在「失败：bluetooth off」，所以会话页、画面等比缩放、连接中
  改设置这三项**尚未在真实设备上验证**，只有单元测试覆盖几何计算。
- 该模拟器 ROM 没有导航栏窗口（`dumpsys window` 里没有 `ITYPE_NAVIGATION_BAR`），第三种模式
  在它上面看不到差别；车机（Android 10）上导航栏由系统绘制，`show(navigationBars)` 才会有效果。
- 显示方式决定 offer 的新逻辑在模拟器上确认过一次：面板 2560×1440、状态栏 54 px 时，日志是
  `display: offering 1920×1038 at 384 dpi (panel 2560×1440, content 2560×1386, …)`，即按可见区域
  等比缩小，而不是固定 16:9 的 1920×1080。手机是否接受这个比例、画面是否真的无黑边，未实车。

| 连接 | 缺权限时的提示与「打开应用权限」 | 立即 | 模拟器：撤销定位权限后按钮出现，点击落到本应用的系统详情页（`InstalledAppDetails`） |
| 连接 | 从系统读取本机蓝牙地址 | 立即 | 模拟器三条路径都验过（无地址 / 地址对但标识未派生 / 已一致）；真实车机能否读到取决于它的 secure 设置与 dumpsys |
| 连接 | 手机蓝牙连上时自动回连 | 立即（下一次 ACL 事件） | 单测决策表；未实车 |
| 连接 | 结束后恢复车机自己的 WiFi | 停止接收端时 | 仅编译；Android 10+ 预期被拒并提示 |
| 连接 | USB 授权自动确认（跳系统无障碍设置） | 用户启用后 | 单测对话框识别；未实车 |

连接页的二维码：与连接码同源，蓝牙地址或机型码一改就重画；地址是占位值时显示一句原因，
不画一个「扫了也连不上」的码。

**只在无线真的开着时才出现**（`running && wirelessOn`）。接收端没启动、或者这一轮是插线唤醒的
（无线关着），都不显示：那时车机根本没在广播，给一个码等于把手机引到一台不存在的车旁边，
而失败看起来像「码不对」。停止无线后二维码一起收起，连接码仍然显示。

## 七、桌面上的第二个入口：直接进设置

车机桌面上有两个图标：

| 图标 | 组件 | 打开后 |
| --- | --- | --- |
| `HiCar` | `HiCarLauncherAlias`（alias → `HiCarHostActivity`） | 连接页（或正在连接的会话页） |
| `HiCar 设置`（滑块图标） | `HiCarSettingsLaunchActivity` | 同一个页面，设置层已展开 |

第二个入口原来是一个 `activity-alias`，现在是一个**只做转交的 Activity**（`Theme.NoDisplay`，
launch 完立刻 `finish()`）。原因：alias 在 `cmd package query-activities` 里存在，但桌面会把同一个
target 的两个 alias 当成一个应用、只留一个图标；真实 Activity 才是一条独立条目。它不画任何东西，
所以不会留下黑帧；转交过去的是 `ACTION_SETTINGS`，`HiCarHostActivity`（`singleTask`）认这个 action
并把 `settingsOpen` 置为 true，连接中再点会走 `onNewIntent`，会话不中断。

**注意：覆盖安装会让桌面少掉其中一个图标。** 这是桌面自己的行为（模拟器 2026-11-25 复现：
`adb install -r` 后桌面只剩一个入口，`adb uninstall` + 重新安装后两个都回来，`query-activities`
始终返回两条）。更新后如果只看到一个图标，从应用列表里把另一个拖回桌面，或者卸载重装 / 重启桌面。

模拟器验证：干净安装后桌面同时出现 `HiCar` 与 `HiCar 设置`；点后者落到 `HiCarHostActivity` 且
设置页已展开；`cmd package query-activities` 两条都在。
